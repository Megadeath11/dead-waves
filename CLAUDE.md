# Dead Waves — project notes for Claude

CoD-Zombies-style wave shooter. **Electron + three.js (r149, `js/vendor/three.min.js`) + steamworks.js 0.4**, same stack as the owner's Tight-Opoly and Dust & Debt (boxer-drift). Steam on the Spacewar test app (**App ID 480**). The owner plays on Windows and wants games that are just an exe in a folder: no Godot, nothing to install.

Ported from Godot 4.5 on 2026-10-23; the Godot project is kept in `old-godot-version/` for reference only.

## Layout
- `index.html` (all CSS) loads plain scripts in order; everything hangs off `window.DW`. No bundler, no modules.
- `js/data.js` tables (guns, perks, difficulties), settings + stats in localStorage. `js/maps.js` ASCII maps + builder. `js/models.js` primitive-built models, `bake()` merges a node's plain meshes into one vertex-coloured mesh; `StaticBatch` merges all map scenery. `js/physics.js` AABB world (`Phys`: move/pushOut/raycast/hasLine) and `Nav` (0.5 m grid, multi-source Dijkstra flow field toward all living players; `steer()` for zombies). `js/world.js` match logic + co-op sync, `js/player.js`, `js/zombie.js`, `js/hud.js` (DOM HUD), `js/main.js` (menus, loop, pointer lock), `js/net.js`, `js/sfx.js` (Web Audio synth), `js/bot.js`.
- `tools/electron-main.js` + `tools/steam-preload.js` expose `window.steam` (lobby create/join/leave/data/list/invite, P2P send, packet batches) and `window.desktop` (copy, fullscreen, quit).

## Gameplay rules worth knowing
- No spread at all (owner's request): shots go along the exact centre ray, hip or ADS, moving or not. Recoil only kicks the view straight up. The crosshair is a dot (red on a zombie), hidden only behind the sniper scope. ADS height is computed per gun so the gun sits under the dot.
- Gun is drawn in a second pass (`player.vmScene`) after clearing depth, so it never clips walls.
- Lights: fixed pool (8 lamp lights assigned to the nearest lamps each frame + muzzle, explosion, 2 power-up lights). Never add/remove lights at runtime (three.js recompiles shaders).
- Progression (owner felt top guns came too fast): wall guns M14 600 / Shotgun 1200 / MP5 1800 / AK 2600; Mystery Box 1950, shut until wave 5 (`BOX_UNLOCK_WAVE`), weighted odds (`BOX_WEIGHT`, Death Machine rarest).
- Bosses (owner asked for harder): Brute max(6000, hp×16), Abomination max(5000, hp×13), ×1.6 per extra player; barely flinch; at 50% HP they enrage (35% faster, shorter ability cooldowns, bigger slam, triple acid). HUD has a bar per boss and a player health bar.
- Downed players are never targeted (`allPlayers('target')`); solo Second Wind counts as down too. Anyone who gets back up gets 3 s of grace (`myGraceT` / remote `graceT`). With no target, zombies back away from downed/grace players (`fleePoints()`, zombie flee mode); game over uses `out` (down with no self-revive coming).
- Limb convention: limbs hang along -Y, positive x rotation swings arms forward (-Z) / bends elbows; knees use negative. The Godot code had this backwards (arms behind the back); fixed in 2.3. Teammate gun pose was fitted numerically so hands sit on the gun.
- 2.3 additions: Pack-a-Poonch desk (map cell `U`, 20000, gem finish via `M.papify` + 4x damage, weapon entry `pap`); grenade wall-buy (cell `G`, 150 each up to 10); wind charge on key 3 (`player.wind`, 3 charges, `world.launchWind/windBlast/windPush`, zombie `knockX/Z`, self-boost `player.windKnock`); insta-kill does 2x to bosses; Goon Lord / Wendygoon (`goonlord`, wave 20 then every 10, lights out via `world.darkness`, lunge + screech); HUD power-up timers, zombie counter (`remaining()/waveTotal`, sent in the zs header), last-zombie and downed/revive markers; teammate shots (`sh`), shared Mystery Box (`box` roll/take), revive progress (`rv`).
- 2.4 additions: maps Harbor + Overpass with decks (`H`, 2.4 m), stairs (`> < v ^`, 8 risers of 0.3), elevators (`E`, player-only, synced with `lift`), lowercase objects on decks; zones up to 9 (door cost 750 + 250 per zone). Nav is height-aware (`Nav.height`, `link()` allows steps <= 0.35; lift cells blocked); walls/doors/pillars collide to 12 m so nobody stands on them. Rule: every open nav cell must be reachable (no zombie-proof pockets) - check with the snippet in the 2.4 session (compute from a player cell with all doors removed). Stations `A` armour (4000, 150 soak), `R` ammo (5000), `T` sentry (8000, 60 s, owner deals the damage). PaP tiers 1-3 (`PAP_COSTS`, `PAP_DMG`), perks mule/dead/stam (cap 7). Jump-headshot crits x2. 30 s intermission, skip vote on Enter (`skip`/`skipv`, host counts).
- 2.5: sentries are placed with T anywhere (`world.placeSentry`, 8000, max 4 per player, 120 s, synced with `sentry`; owner deals damage); map `T`/`t` cells are now plain floor. Tab board shows money/earned/kills/HS%/revives/downs/bosses/sentries/ping; clients ping the host each second (`ping`/`pong`) and share it in `ps.pg`. HUD show/hide must set an explicit display value ('block'), never '' (CSS defaults several panels to display:none - that hid the scoreboard, scope and hold-E bar until 2.5).
- Goon Lord model (2.5.4) follows the owner's reference picture: own skeleton in `M.wendygoon` (lanky, dark mottled fur, deer-skull head, grey antlers, white eyes/teeth/ribs/claws, back spikes) with `rig.hipY/neckY/headC` used by the shared animation and hit boxes; scale 1.75 (~3.7 m, twice a player); runs at 4.4 and shakes hard every frame while moving.
- Goon Lord entrance (2.5.5, `world.startGoonIntro/updateGoonFx`, runs on every client): music stops, `dread` rumble + strobing lamps (`flicker`) + scary centre text, blackout at 2.6 s; on reveal it stares `GOON_STARE` s (zombie `stareT`, host AI) then `shriek` + `camShake`; heartbeat/whispers/`.scare` vignette scale with distance; `goonLight` lights its face. Camera shake only moves/rolls the camera, never its aim.
- Settings (2.6): `DW.SETTING_DEFAULTS` in data.js, tabbed panel in `UI.settingsPanel` (main menu + pause). Quality presets (`DW.QUALITY_PRESETS`) set renderScale/shadows/aa/lights/particles; touching one by hand shows Custom. Renderer side in `main.js applyGraphics` (pixel ratio = dpr x renderScale, exposure x brightness, FPS cap in the rAF loop, `#fps` counter), shadows live via `world.applyGraphics`, lamp-light count only at match start, AA only at launch (WebGL context). Audio buses: master (muted while unfocused if set) -> music / sfx (`Sfx.applyVolumes`); menus play their own `menu` track. Keys: `Input.applyBinds/bind/keyName`; only the first key of an action is rebindable, taking another action's key swaps them; HUD prompts written with "E" are rewritten to the bound key in `hud.setInteract`. Crosshair/HUD size are CSS vars `--xh/--xhs/--hud` on #ui.
- Dodger (2.6.1, `dodger`, appended to ZTYPES since the index is in snapshots): from `DODGER_WAVE` 6, 3%/wave up to 20% of spawns, speed 2.6-3.1, 0.85 hp. Host-side `Zombie.dodge()` checks `world.aims` (every living player's eye+forward, built each hostTick from local player and remote yaw/pitch): aim ray within 1.1 m + LOS -> 0.3-0.42 s sidestep across the aim line (alternating, nav-checked), 0.45-0.8 s cooldown. Lean in `animate` comes from actual lateral motion so clients see it.
- 2.7: lobby no longer flashes (host `pushNames` only writes when the names JSON changed - each write fired a lobby update that called it again; `onLobbyUpdated` redraws only on a changed signature and without the entry animation via `.screen.still`). PaP tiers double mag/reserve (`DW.magOf/reserveOf`, use these instead of `wd.mag`). Downs keep perks and guns (solo Second Wind is used up by its self-revive); `revive()` drops one PaP tier on every gun. Bleed-out / Second Wind bar (`.bleed`) and bars on teammate down markers (`.mk-bar`). Quit-to-menu asks first (`hud.confirmQuit`). Reload animations in `player.reloadPose` (styles per gun in `RSTYLE`; gun models put moving parts in `g.userData.mag/bolt/pump/lid/cells` sub-nodes via `pbox/pcyl`, the support hand is `player.leftHand`). Maps Crossroads (open, 4 zones) and Proving Grounds (44x30, one zone, every shop on the north wall), generated by a script (W/G on the top border are fine: they build as wall).
- Metalness is scaled by 0.3 (no env map), ambient ×1.35 vs the Godot values.

## Co-op
Lobby owner is host: simulates zombies/waves/power-ups; clients simulate their own player and send hits. Packets: byte 0 = 0 + UTF-8 JSON `[type, data]`, or byte 0 = 1 + float32 zombie snapshot (`zs`, 15 Hz, unreliable). Names travel via `hello` messages and the host's `names` lobby data (steamworks.js can't read friend names). steamworks.js 0.4 has no lobby filters, so "Join co-op game" also offers invites and lobby codes; the open-games list may miss lobbies on busy Spacewar.

## Leaderboards
steamworks.js 0.4 has no leaderboard API, so the Steam boards from the Godot version are gone; the Leaderboards screen shows local runs. Bringing Steam boards back would need an FFI package (e.g. koffi) calling steam_api64's ISteamUserStats flat API.

## Build / test
- `bash tools/build-exe.sh` → `dist/DeadWaves-<ver>-portable.exe`; copy to `DeadWaves.exe` at the folder root. Builds in `~/dead-waves-build` (node_modules copied from `~/boxer-drift-build`, Electron 33.4.11 zip is cached, so it works offline).
- `node tools/serve.js` → http://127.0.0.1:8650/ ; `.claude/launch.json` has it as `dead-waves`.
- Bot: `?playtest&map=bunker&diff=1&seconds=600&speed=6&god=1` (`start_wave`, `skill`). Logs per-wave lines and `ISSUE [...]`. When the browser pane is hidden, rAF stops; the loop falls back to a timer while a bot runs (`DW.forceLoop = true` does the same for manual tests).
- Co-op without Steam: two tabs `?fake=1001` / `?fake=1002` (BroadcastChannel + localStorage lobby).
